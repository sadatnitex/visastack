# P1 plan (Lane B): honest necessity, alternatives, route applicability (R02-R07, R09)

Base: `umpe/p1-requirements` from `origin/umpe/contracts-necessity` (main 9461ebe5 + 7702f900). Binding: ADR 0026 D1-D3, lead brief decisions 1-7.

1. Schema and migration 0116 (additive, nullable, re-runnable): enums `requirement_necessity`, `requirement_provenance`, `requirement_group_mode` built from the shared core lists; `pack_requirements.necessity`, `provenance`, `group_key`, `group_mode`; `pack_versions.manifest_format`. Generated with drizzle-kit, then the SQL made re-runnable in the 0114/0115 style. One check: `group_key` and `group_mode` are set together.
2. Missing-column tolerance: one probe in packs.ts (information_schema, remembered only once the columns exist). Reads of pack versions and requirements pick the full or the legacy column set and fill the new fields with null. Pack Studio writes refuse with a plain message until the migration runs (drizzle inserts name every column, so a write cannot succeed before it).
3. Manifest: `buildManifest(rows, format = 1)`. Format 1 untouched. Format 2: `{ formatVersion: 2, requirements }`, legacy five keys first, then necessity, provenance, groupKey, groupMode, condition only when non-null, UTF-16 sort. Approve picks format 2 only when a row uses a new field and stores `manifest_format`; verify and the manifest download use the version's own format.
4. Authoring: `addRequirement` validates necessity and provenance against the shared lists, CONDITIONAL needs a valid condition, group key and mode together, stored `optional` from `optionalFlagFor`. Approve and publish re-check every stored condition (and CONDITIONAL rows) and refuse in plain words.
5. Readiness (missions.ts): summaries carry necessity, provenance and groupKey only when authored, so legacy shapes stay identical. Blocking uses `necessityCanBlock`. ANY_OF groups collapse into one unit: satisfied when any applicable member is, counted once, one missing entry listing the alternatives; a group blocks only through a blocking member. Unsatisfied members of a satisfied group read as non-blocking. Format 2 versions fail closed on an invalid stored condition (UNVERIFIED); format 1 keeps today's fail-open reading.
6. Matching: `PackMatchTerms.route` (optional). Known route mismatch excludes; a pack with a route and an unknown case route is listed with `coversRoute: false` and never auto-linked.
7. R09 guard test: static destination data never yields readiness or an auto-linked pack.
8. UI: Pack Studio add form gains Necessity, Who Asked for It, When It Applies (rule) and Any One of These group; case checklist rows show the necessity label for authored rows, the provenance when not official, and the alternatives under "Any One of These". Legacy rows unchanged.
9. Tests: golden v1 untouched, v2 golden checksum, old version verifies after migration, group no double count, recommended never blocks, conditional unknown is Unverified, invalid v2 condition fails closed, approve refuses invalid conditions, route mismatch and unknown route, sharing categories untouched, static destinations guard, 0116 on PGlite, missing-column tolerance. Two guards proven red.
10. Verify (lint, typecheck, focused vitest, db drift), `/code-review max`, fix, push.

Gaps expected: cases carry no route, consular location or travel-date applicability for matching; agency triage and other per-item consumers outside this lease still count group members one by one.
