# P7 hand-back (Lane C2): stopped before sharing code, by design

Branch umpe/p7-account-response from origin/main 5aea5d63. Docs only (this file, P7-PLAN.md). No code, schema or shared file touched, so no full check, review or guard proof ran. Final SHA: the commit adding this file.

## Finding
The existing model cannot give an agency only the exact versions a traveller approves.
- Grants scope to whole documents (grants.document_ids, category snapshot). Policy resources carry no version (packages/policy/src/authorize.ts:96-124).
- accessDocument (packages/services/src/documents.ts:1328-1336), the agency's read path, always serves the latest version. A document-level grant would expose any version uploaded after submission, which breaks "later file changes never alter the submitted response".
- Facts are shared only by live category grants; no fact-version scope exists.
- ADR 0017 exceptions hide cases, not versions.

## Options
| Option | How | Strength | Cost and risk |
|---|---|---|---|
| A. Version-pinned grant | Add grants.document_version_ids and fact_version_ids; policy Grant and resource gain a version; accessDocument serves the pinned version when the grant pins | Reuses every existing control: revoke, expiry, step-up, audit, Sharing page | Edits policy, documents.ts, sharing.ts and the ratchet (all outside P7); a new permission law and an ADR; every grant consumer must learn the pin |
| B. Response-scoped read path (recommended) | Agency reads only through new umpe-collection-response services that take the immutable response record as proof and serve exactly its version ids, through a version-exact helper extracted from accessDocument | No grant at all, so nothing broader can leak; the same request-scoped review queue P9 needs for guest manifests serves both branches | One lease on documents.ts to extract the helper; the traveller needs a Withdraw action and a line on their Sharing page; P9 and P7 must share the manifest reader |
| C. Frozen copy | Copy the approved version bytes into request-scoped agency intake storage at submission | Simplest isolation; identical to the guest model | Duplicates personal data; traveller erasure and retention must reach the copies; storage cost |
| D. Document-level grant | Existing createGrant with document_ids | No new code | Rejected: later versions become visible; broadens access |

Recommendation: B, with A only if the owner wants agency responses to appear as ordinary grants on the Sharing page.

## What P7 needs from others once a path is chosen
- P6 or P8: an exported reader that turns the request-scoped session (P8) into request id, issued revision id and recipient email hint. openCollectionLink returns only linkId today, so /collect/account has no supported way to read the email hint.
- Lead: a documents.ts lease for B (or policy, sharing.ts and documents.ts leases for A).
- Notification: an agency notice "Submitted to Agency" event, added by the lead after P8 merges.
- Owner: choose A, B or C.
