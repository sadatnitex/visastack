# UX12 hand-back: Delete My File (no migration, switch off by default)

- Owner request (3 Nov 2026): the owner could not remove a document of someone else's that had been added by mistake, because Ask Us to Remove This File needs staff approval. The owner approved an instant, verified, owner-only "Delete My File" (decisions 1 to 10 of the plan, all at the recommended defaults). It reverses D1 for the record owner's own files, recorded as decision row D12 in `docs/roadmap/lifecycle/PROGRAMME.md` (the plan called it D11, but D11 was already taken by "Parallel execution", so the next free number was used).
- What changed (nothing at all while `DOCUMENT_SELF_DELETE` is off, which is the default):
  - Manage menu: a last item, "Delete My File", for current and archived documents with no legal hold. "Ask Us to Remove This File" stays. A waiting request for the same file is closed as Completed by the deletion.
  - Confirmation (lean): "Delete [name] Now?", "This removes the file from VisaStack for good. It cannot be undone.", one short line for each thing the file touches that is not zero (agencies, open cases, profile details, AI apps, trips, hand-overs), the backup note, "Type DELETE to Confirm", one filled danger button "Delete File Now" and "Cancel". Result: "Removing securely. Record D-xxxx is in Removal Records."
  - Refusals in plain words, with a pointer to Ask Us to Remove This File when that is switched on: a legal hold, a finished or submitted case, an agency's request or answer (including a document request's answer that was not withdrawn).
- Services (`packages/services/src/lifecycle/removal-requests/`):
  - `effects.ts` (extracted with no behaviour change, first commit): the impact count, the open-case effects (selection removed, task, revision bump), the agency notice and the uploader role, now shared by support's approval and Delete My File so the two cannot drift. `duplicates/status.ts` gained `documentBlockReasons` (the D5 reasons for one document as a set); the first-reason logic is unchanged. Every helper takes a lifecycle access proof, so the access ratchet baseline did not change.
  - `self-delete.ts`: `previewDeleteMyFile` and `deleteMyFile`, typed to `AuthorizedApplicant<'MANAGE'>`, with the proof checked again at run time (owner role, same applicant). One transaction in lock order: the traveller row, then the document row, then legal hold, refusals and the impact, all under those locks. Stale guard: if any count is now higher than the person confirmed, nothing is deleted and they look again. The typed word is checked in the service (trimmed, any case). The fresh sign-in is decided under the locks (`step_up_required` when the file is shared or an open case uses it), never by the caller. Rate limit `DOCUMENT_SELF_DELETE`, 10 an hour per account, counted once the deletion is certain and kept when refused. Receipt: path REQUEST, requested by the owner, no approver, codes and counts only. Then `enqueueDocumentRemoval` (a BLOCKED result rolls everything back). Audit `DOCUMENT_SELF_DELETED` (path SELF, counts, no names) and the product event of the same name. The owner is told by email and in the app after every deletion, so a deletion from a stolen session is noticed.
- Web (`apps/web/src/app/app/applicant/[id]/documents/manage/self-delete/`): `actions.ts` (purpose `owner_document_self_delete`, proof by document then applicant, switch checked first, step-up with a return to the same confirmation, erasure worker started after the commit with `after`, refusal mapping), `messages.ts`, `self-delete-action.tsx`; `registry.tsx`; `request/facts.ts` and `view.ts` carry the switch and read the hold fact when either switch is on; `lib/env.ts` `documentSelfDeleteOn()`; one CSS block `WP-UMPE-UX12` at the end of `globals.css`.
- `DOCUMENT_ACTIONS` gained `DELETE_MY_FILE` at the end (the frozen list is otherwise unchanged; the owner approved this edit by the decision). `availableDocumentActions` takes an optional `selfDeleteSwitchOn` that defaults to off.
- Owner action: set `DOCUMENT_SELF_DELETE=on` in Vercel Production to turn it on. No migration is needed (path REQUEST is reused).
- Decisions where the plan was silent: the typed word ignores case and surrounding spaces (a phone capitalises the first letter); a fresh sign-in is also asked when the file is shared by name with anyone (not only with agencies); agencies given the file by name, not only those on an open case, are told (owners and admins, without the file name), because the screen says agencies are told; a file only an unwithdrawn agency answer used is refused, a withdrawn one no longer keeps it; a waiting removal request is closed as Completed with no decision code; the owner's notice says "if this was not you, secure your account and contact support".
- Not covered, by design or not checked: agencies that can reach the file only through a share of a whole category or the whole profile (not by name, not through an open case) are not counted or told; a live package choice of an open case that is not also a selected document is removed with the file by the database without a revision bump (the same gap exists in support's approval); a Kept result after a late legal hold is shown in Removal Records but, unlike support's approval, the daily sweep does not send the owner a separate notice for it.
- Not verified: a real phone, a screen reader, dark appearance, the live signed-in flow (switch off in production), the browser checks (CI runs them), the AI app read paths beyond the static read-path guard.
