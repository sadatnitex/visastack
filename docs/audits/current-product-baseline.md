## Known defects

**P0 — resolved in PR #40 (merged, production-verified)**
- **Preview served original bytes under a "redacted" label.** `/api/blob/[key]` returned the stored original bytes for any valid token regardless of the signed `variant`; `previewDocument` minted a `redacted` variant for everyone. *Fixed:* the serving route fails closed for any non-`original` variant (HTTP 501), and `accessDocument` mints an `original` preview only for the applicant owner; third parties get `redacted`.
- **Identity keyed by mutable email**, not the immutable WorkOS user id. *Fixed* — `workos_user_id` binding (migration `0010` + `provisionAccount` rewrite + 6 tests); email is now mutable contact data. Follow-up still open: make the column NOT NULL after all live users are bound.

**P0 — resolved on this branch (Storage PR, not yet deployed)**
- **Object storage path leaked applicant identity.** Upload objects were keyed `${applicantId}/${uuid}` — the applicant id was directly recoverable from the storage path. *Fixed:* object keys are now bare, opaque UUIDs; the applicant/document association lives only in the domain tables.
- **`Content-Disposition` never carried the approved display filename** — served bytes as an anonymous stream. *Fixed:* the filename is now part of the signed blob-access token payload (tamper-proof) and flows through to both the classic and RFC 5987 `Content-Disposition` forms.

**P1 — resolved this round (job queue, not yet deployed)**
- **Upload processing was synchronous and blocked the HTTP response.** *Fixed:* processing now runs via a DB-backed job queue (`processing_jobs`, migration `0011`) triggered by `after()` post-response, with a Vercel Cron sweep as a durability backstop. See the "Upload processing pipeline" matrix row above for detail. Not yet Production verified — no live deployment of this branch yet.

**P1 — resolved this round (UI completeness, not yet deployed)**
- **A failed job parked at `FAILED` with no admin UI to inspect/retry it.** *Fixed:* `listFailedJobs`/`retryFailedJob` (`packages/services/src/jobs.ts`) plus an admin "Failed intake jobs" card showing document name, attempts/maxAttempts, last error, and a one-click retry (resets to `PENDING`, `attempts: 0`, `availableAt: now()`).

**P1 — resolved in PR #45 (Processing PR, merged, production-verified)**
- **`EXTRACTING` was a no-op — no automatic naming, no document intelligence at all.** *Fixed:* real embedded-text extraction (PDF/DOCX/TXT/MD), rules-based classification (passport/bank statement/employment certificate), and a filename-proposal review UI, all persisted per §13's scoped table set. See the three new matrix rows above. Confirmed production-healthy via the Deploy Smoke workflow against commit `7b91125`.

**P1 — resolved this round (storage fail-closed fix, not yet deployed)**
- **`createStorage()` silently fell back to reduced-control `NeonBlobStorage` in every environment alike, including production, when `BLOB_READ_WRITE_TOKEN` was absent.** *Fixed:* it now fails closed (throws) specifically when `VERCEL_ENV === 'production'` — a real deployment must never silently degrade to reduced-control storage for genuine evidence. Local dev, automated tests, and PR previews are unaffected (the master directive's own §3 taxonomy classifies pull-request previews as "development" mode, where the Neon-bytea fallback remains the correct, approved behavior — using Neon-bytea itself was never the deviation, only the missing production guard). 5 new tests in `apps/web/src/lib/storage.test.ts`.

- Document download has no UI path for either the owner or a grant recipient — not an oversight; blocked on step-up authentication (see the "Document download" matrix row above), which does not yet exist anywhere in the app.

## Current security exceptions (must remain visibly labelled)

- **Reduced-control storage fallback:** `NeonBlobStorage` (bytes in Postgres) remains the fallback backend in local dev/tests/PR previews whenever `BLOB_READ_WRITE_TOKEN` is unset — acceptable only for synthetic/internal testing, dev, and legacy data; not the sensitive-document production design. In production, `createStorage()` now fails closed (throws) instead of silently using it — fixed this round. `VercelPrivateBlobStorage` is the active production backend (token configured, redeploy confirmed clean), but a real upload→serve round-trip has not yet been exercised against live traffic.
- **Reduced-control scanning:** structural scanner is not antivirus; real-data upload must stay gated until a real malware control is active.
- **No true redacted rendition:** third-party preview is fail-closed (disabled) until real renditions ship. As a direct consequence, no document download UI exists for any party (owner or third party) — see the "Document download" matrix row.
- **No step-up authentication:** `DOWNLOAD_ORIGINAL` requires `stepUpSatisfied: true` (policy engine, `packages/policy/src/authorize.ts`) but no flow exists to satisfy it. This is why a Document Download button was deliberately not built this round rather than shipped as a security shortcut.

### Follow-up fix this same round: two real defects found by automated PR review (PR #47, `chatgpt-codex-connector[bot]`)

The initial `looksLikePlainText()` heuristic (above) had two genuine bugs, both fixed before merge:

1. **P1 — stored XSS via spoofed content type.** The heuristic accepted *any* clean-UTF-8, control-character-free byte content as "safe text" regardless of the object's declared `contentType`. HTML and SVG source are both ordinary UTF-8 text with no control characters — structurally indistinguishable from a real TXT/MD file by content alone. A caller that bypasses the browser file picker (a direct Server Action call, which is not gated by the `accept` attribute) could declare `contentType: 'text/html'` or `'image/svg+xml'` with actual `<script>` payloads, have the scanner mark it `safe`, and have `/api/blob/[key]` later serve it `inline` under the app's own origin — real stored XSS (HTML execution or SVG script execution). **Fix:** gated the plain-text path to an explicit allow-list, `PLAIN_TEXT_CONTENT_TYPES = {'text/plain', 'text/markdown'}` — an upload declaring `text/html`/`image/svg+xml`/anything else is rejected regardless of byte content. Also added `X-Content-Type-Options: nosniff` to `/api/blob/[key]`'s response headers as defense in depth against browser MIME-sniffing.
2. **P2 — UTF-8 truncation false negative.** The original heuristic decoded only a fixed-size byte prefix, which can split a multi-byte UTF-8 sequence exactly at the cut boundary and wrongly reject a perfectly valid non-ASCII text file larger than the sample size. **Fix:** decode the whole (already size-bounded, ≤25 MiB) byte array instead of a truncated sample.
3. **Tests** — 2 new cases added to `packages/adapters/src/adapters.test.ts`: spoofed `text/html`/`image/svg+xml` content rejected despite clean bytes (stored-XSS regression), and a >8KB file with a multi-byte CJK character straddling the old sample boundary now accepted (truncation regression). Full adapters suite: 28/28 passing.
4. This baseline audit, updated to reflect the above truthfully.
