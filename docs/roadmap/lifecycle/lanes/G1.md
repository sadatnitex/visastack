# LC-G1 Profile: No Longer Current and Ended

- Wave 0. Branch: `claude/lc-g1-profile`. Depends on: nothing (no new tables). Allowlist: `../allowlists/G1.txt`.
- Read first: `../PROGRAMME.md` sections 1, 2, 6, 7.

## Objective

A person can say "this is no longer current" about one value, and "this ended" about one entry in a list (an old address, a past job), while every earlier version stays in history and old case snapshots stay exact.

## Build

1. `packages/services/src/lifecycle/profile/`: `markFactNotCurrent(access, { factId })` appends a new fact version with no value and status `STALE` (both exist today: `fact_versions.value` is nullable, `STALE` is in `FACT_STATUSES`), and `markRecordEnded(access, { recordGroupKey, repeatingRecordKey, endedOn })` using the existing `fact_versions.valid_until` column. A repeating record is several facts sharing one `facts.repeating_record_key`: verify first how the profile reads a record, then append one version per fact of that record carrying `valid_until`, in one transaction. Owner only, through `requireAccess`. Protected-field encryption semantics unchanged (no value means nothing to encrypt). Audit `FACT_MARKED_NOT_CURRENT`.
2. Display: render a `STALE` current version as "No Longer Current" in `profile-editor.tsx` from the status the profile read already returns; do not edit `listFactHistory` or `listApplicantProfile` (WP-SB1 owns them, PROGRAMME 5.3). Readiness: in `missions.ts`, only the field-requirement check, a `STALE` current version counts as unanswered unless the field is marked "Does Not Apply" (never `listMissionSnapshots` or `listTasks`, WP-SB2; document matching belongs to A1).
3. Profile editor: "No Longer Current" on a single value, "Ended" on a list entry, both reversible by entering a new value.

## Red first

Today an empty value is refused and there is no way to clear one (prove the gap with a test of the new function first).

## Acceptance

Prior versions listed in history; a case snapshot taken before still shows the old value; readiness treats the field as missing; agency members cannot use it; protected field still encrypted when a value is entered again.

## Not yours

Anything under documents or travellers.
